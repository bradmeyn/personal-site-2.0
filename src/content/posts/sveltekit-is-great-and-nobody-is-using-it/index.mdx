<TextBlock>
  For years, <LinkBlock href="https://svelte.dev/">Svelte</LinkBlock> and its
  meta-framework SvelteKit have quietly been among the best options for building
  full-stack TypeScript applications on the web. SvelteKit offers excellent
  performance with far less boilerplate than most React-based frameworks. Even
  so, it still hasn't gained the same traction: Next.js remains the default
  choice for many new projects, driven by mindshare, hiring inertia, and the
  gravitational pull of the React ecosystem. In this post, I want to explore why
  SvelteKit is great and why I think it deserves more attention.
</TextBlock>

<HeadingBlock>Simplicity</HeadingBlock>
<TextBlock>
  Svelte apps typically require less code than their React or Vue counterparts.
  State can be declared with <code>let framework = $state("React")</code>, then
  updated directly with <code>framework = "Svelte"</code>. Need an input to keep
  state in sync? Add <code>{"bind:value={firstName}"}</code> and you're done, no{" "}
  <code>{"onChange={handleChange}"}</code> ceremony needed. See a{" "}
  <LinkBlock href="https://component-party.dev/?f=svelte5-react#form-input.input-text">
    side-by-side comparison
  </LinkBlock>{" "}
  for more examples. It feels intuitive, and it helps you ship the same features
  with less code.
</TextBlock>

<HeadingBlock>Performance</HeadingBlock>
<TextBlock>
  Most React developers have experienced accidental re-renders that quietly drag
  performance down. Svelte's signal-based reactivity avoids that class of
  problem by updating only the DOM that actually changed. The result is better
  performance as apps grow, without constantly reaching for{" "}
  <code>useMemo()</code> or <code>useCallback()</code> to keep things fast.
</TextBlock>

<TextBlock>
  SvelteKit also ships less JavaScript to the browser thanks to its
  compiler-first approach, which helps it post excellent{" "}
  <LinkBlock href="https://httparchive.org/reports/techreport/tech?client=mobile&tech=Astro%2CNext.js%2CNuxt.js%2CSvelteKit&geo=ALL&rank=ALL&page=1">
    Core Web Vitals
  </LinkBlock>{" "}
  numbers, right alongside Astro, one of the strongest performers in the static
  site space.
</TextBlock>

<HeadingBlock>Ecosystem</HeadingBlock>
<TextBlock>
  React has the largest ecosystem of libraries and tools, but Svelte's ecosystem
  is growing rapidly and thanks to the ability to use vanilla TypeScript, can
  easily integrate with many existing libraries. All the tools you'd need to
  build a modern web app are available:
</TextBlock>

- Components: <LinkBlock href="https://svelte.dev/community#components">Svelte component libraries</LinkBlock>
- Auth: <LinkBlock href="https://better-auth.com/docs/integrations/svelte-kit">Better Auth SvelteKit integration</LinkBlock>
- Charts: <LinkBlock href="https://www.chartjs.org/">Chart.js</LinkBlock> or <LinkBlock href="https://next.layerchart.com/">Layer Charts</LinkBlock>
- ORM: <LinkBlock href="https://drizzle.team/">Drizzle ORM</LinkBlock>
- Icons: <LinkBlock href="https://lucide.dev/guide/svelte/">Lucide Icons</LinkBlock>
- Global state management: Built in with <code>svelte.ts</code> files.
- Form handling: Built in with <code>form()</code> remote functions.

<HeadingBlock>Why Isn't Svelte More Popular?</HeadingBlock>

<TextBlock>
  React is the default, the safe choice with a wider ecosystem and more job
  opportunities. AI-driven devlopment is also likely to favour React (although
  I've seen it misuse <code>useEffect()</code> more than once). Svelte's
  simplicity and performance benefits may not be enough to overcome the inertia
  of the React ecosystem, especially for larger teams and projects that require
  a lot of third-party libraries.
</TextBlock>
